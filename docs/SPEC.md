## 1. Config schema (the contract everything hangs on)

Pydantic models in `app/schemas/config.py`, exported to JSON Schema at
`docs/config.schema.json` (generated by a script, committed).

```jsonc
{
  "config_version": 3,
  "sheet_id": "1AbC...",
  "org_id": "org_...",
  "schema_hashes": { "Orders": "a91f...", "MACHINES": "77c2..." },
  "header_row": 2,
  "data_start_row": 3,
  "canonical_headers": [
    { "canonical": "DISPATCH DATE", "match": ["contains:DISPATCH"] },
    { "canonical": "FREEZE?",       "match": ["contains:FREEZE"] },
    { "canonical": "STATUS",        "match": ["equals:STATUS"] }
  ],
  "enums": {
    "STATUS": {
      "stages": [
        { "value": "IN-PROCESS", "match": "contains:PROCESS",  "order": 1 },
        { "value": "COMPLETED",  "match": "contains:COMPLET",  "order": 2 },
        { "value": "DISPUTED",   "match": "contains:DISPUT",   "order": 3 },
        { "value": "DISPATCHED", "match": "contains:DISPATCH", "order": 4 },
        { "value": "CANCELLED",  "match": "contains:CANCEL",   "order": 5 }
      ],
      "unknown_order": 99
    }
  },
  "rules": [
    {
      "id": "sort_by_stage",
      "tabs": "all_with:STATUS",
      // FREEZE? is listed because status_formatting (chained below) depends on it;
      // every column a chained format rule reads must fire the chain (M2 clarification).
      "trigger": { "on_edit": { "columns": ["STATUS", "DISPATCH DATE", "FREEZE?"] } },
      "action": "sort",
      "keys": [
        { "column": "STATUS", "using_enum": "STATUS" },
        { "column": "DISPATCH DATE", "order": "asc", "blanks": "last", "type": "date" }
      ]
    },
    {
      "id": "status_formatting",
      "tabs": "all_with:STATUS",
      "trigger": { "after": "sort_by_stage" },
      "action": "format",
      "row_rules": [
        { "when": { "enum": "STATUS", "is": "IN-PROCESS" }, "font": "#FF0000" },
        { "when": { "enum": "STATUS", "is": "COMPLETED" },  "font": "#008000" },
        { "when": { "enum": "STATUS", "is": "DISPUTED" },   "font": "#D4A017" },
        { "when": { "enum": "STATUS", "is": "CANCELLED" },  "font": "#000000", "strike": true },
        { "when": { "all": [ { "enum": "STATUS", "is": "IN-PROCESS" },
                              { "date": "DISPATCH DATE", "before": "today" } ] },
          "font": "#000000", "background": "#FCE4EC" }
      ],
      "cell_rules": [
        { "column": "FREEZE?", "when": { "equals": "YES" }, "font": "#008000" }
      ]
    },
    {
      "id": "summary",
      "trigger": { "debounced": { "quiet_seconds": 120 } },
      "action": "consolidate",
      "sources": "all_with:STATUS",
      "target_tab": "SUMMARY",
      "prepend_columns": [ { "name": "SOURCE SHEET", "value": "tab_name" } ],
      "derived": [ { "name": "Type of Work", "fill_if_empty": "tab_name" } ],
      "sort_like": "sort_by_stage",
      "lock": true
    }
  ],
  "guards": {
    "max_rows_per_run": 500,
    "snapshot_destructive": true,
    "hold_column": "!hold"
  }
}
```

Rules for later format/consolidate details (widths, banding, date format
matching) mirror the reference implementation in `/engine/reference/legacy.gs`
(the hand-written script this generalizes — commit it as fixture/reference).

**Validator behavior:** unknown action → reject; rule referencing a canonical
header not in `canonical_headers` → reject; enum reference missing → reject;
cycles in `after:` chains → reject. Validation errors are structured
(json-pointer + message) so the agent can self-correct.

## 2. Database schema (Postgres, Alembic)

- orgs(id, name, created_at)
- sheets(id, org_id FK, google_sheet_id UNIQUE, title, status
  [ENROLLING|ACTIVE|PAUSED_DRIFT|PAUSED_MANUAL|ERROR], engine_version,
  service_account_ok bool, created_at)
- profiles(id, sheet_id FK, version, body JSONB, created_at)
- configs(id, sheet_id FK, version, body JSONB, schema_json_version,
  status [DRAFT|PENDING_APPROVAL|ACTIVE|SUPERSEDED|REJECTED],
  source_instruction TEXT, created_by [agent|human], approved_by, approved_at)
- runs(id, sheet_id FK, config_version, rule_id, trigger_type,
  rows_affected INT, duration_ms INT, status [OK|RETRY_EXHAUSTED|PAUSED_DRIFT|ERROR],
  error TEXT NULL, snapshot_id FK NULL, created_at)  -- index (sheet_id, rule_id, created_at)
- snapshots(id, sheet_id FK, run_id, tab, range_a1, body_gz BYTEA, created_at)
- events(id, sheet_id FK, payload JSONB, received_at)  -- raw webhook pings
- flags(id, sheet_id FK, class [B|C], detail JSONB,
  status [OPEN|PATCH_PROPOSED|RESOLVED|DISMISSED], proposed_config_id FK NULL,
  created_at, resolved_at)
- llm_calls(id, org_id, purpose [onboard|repair|audit], model, input_tokens,
  output_tokens, cached_tokens, cost_usd NUMERIC, created_at)

## 3. API surface (FastAPI, /api/v1, service-token auth for MVP)

- POST /sheets {google_sheet_id, instruction} → enroll, kicks onboarding job
- GET  /sheets, GET /sheets/{id} (status, active config, open flags, recent runs)
- POST /sheets/{id}/pause | /resume | /undo {run_id | rule_id+since}
- GET  /configs/{id}, GET /sheets/{id}/configs
- POST /configs/{id}/approve | /reject {reason}
- POST /configs/{id}/dry-run → {per_tab: rows_moved, formatted, warnings[]}
- POST /webhooks/edit  {sheet_id, tab, range, actor, secret} → 202, enqueue
- POST /webhooks/log   {sheet_id, runs:[...]} → 202 (batch ingest from engine)
- GET  /flags?status=OPEN, POST /flags/{id}/approve-patch | /dismiss
- GET  /fleet/summary (counts by status, open flags, error rate 24h)

Webhook auth: per-sheet shared secret issued at deploy, stored hashed.
Drop events where actor == service account email (feedback-loop guard,
belt-and-suspenders alongside the engine's own suppression).

## 4. Workers (RQ)

- execute_run(sheet_id, rule_ids, reason): server-side execution path used for
  cron rules, undo replay, and drift-recovery re-runs. Shares the SAME rule
  evaluator as dry-run (CLAUDE.md invariant).
- debounce: webhook enqueues `run:{sheet_id}` with 5s delay, re-arming on new
  events; global token bucket 250 writes/min across fleet.
- ingest_log: anomaly checks per run — rows_affected > p95(rule, 30d)*3 →
  flag; duration_ms > 240000 → warn; new enum value in rule-referenced column
  (from engine's value census in log payload) → Class C flag.
- drift_check(sheet_id): re-profile, diff, open Class B flag, invoke repair
  agent to attach a proposed patch (PENDING_APPROVAL, never auto-apply).
- weekly_audit: per active sheet — re-profile, distribution diff vs stored
  profile, rules-fired-rate vs history; open flags on deviation. Haiku only.

## 5. Engine.gs contract

Single file, plain V8 JS, no external deps. Generalizes
`/engine/reference/legacy.gs` (committed as the behavioral reference).

Responsibilities: load config from Script Properties → onEdit pre-flight
(governed tab? governed column? header hash match?) → execute matching rules
as batched ops → append run record to local queue → flush queue to
POST /webhooks/log (UrlFetchApp, async-best-effort, keep on failure).
Debounced consolidate via dirty flag in Script Properties + 1-min time trigger.
`!hold` rows: filtered out of every rule's candidate set before evaluation.
On hash mismatch: set status PAUSED_DRIFT in properties, log, do nothing else.
Engine version constant at top; reported in every log batch.

Behavioral parity requirement: run against a copy of the reference workbook;
sort order, colors, overdue tint, freeze text, and SUMMARY output must match
legacy.gs output. This is M2's exit test.

## 6. Agents (plain Anthropic tool-use loops in app/agent — no frameworks)

Onboarding agent tools (read-only + propose):
- get_profile(sheet_id) — cached, from profiles table
- sample_rows(sheet_id, tab, n<=50)
- propose_config(config_json) → runs validator, returns structured errors
- run_dry_run(config_id) → summary the agent can sanity-check

Loop: compile → validate; on failure, retry with errors in context (max 2 on
haiku-4-5, then 1 on sonnet-4-6, then open a human ticket/flag). On validator
pass → create config PENDING_APPROVAL + dry-run result stored. STOP. Human
approves via API/dashboard.

Repair agent: input = old profile, new profile, active config, diff. Output =
classification {benign|ambiguous} + patch (benign) or specific question text
(ambiguous). Patch goes through the same validate → dry-run → PENDING_APPROVAL
path. Never a second path.

Prompt files live in app/agent/prompts/*.md, versioned in git. Profile content
is sent with cache_control for prompt caching. Log every call to llm_calls.

## 7. Frontend (React, minimal, ship-quality not pretty)

Pages: Fleet (table: sheet, status, last run, open flags), Sheet detail

## 8. Milestones with exit criteria (build order is law)

- **M1** Config schema + validator + evaluator + dry-run, pure Python.
  Exit: pytest green incl. fixtures reproducing legacy.gs semantics
  (stage sort, overdue tint, freeze cell, consolidate union+canonicalization);
  invalid-config corpus all rejected with structured errors.
- **M2** Engine.gs. Exit: behavioral parity with legacy.gs on the reference
  workbook copy (manual paste-in install acceptable at this stage).
- **M3** Registry + deployer + snapshots + undo. Exit: enroll via API with a
  hand-written config → engine auto-deployed via Apps Script API → destructive
  run snapshotted → undo restores exact prior state.
- **M4** Webhook/debounce/logs/anomaly/drift-pause. Exit: burst of 10 edits
  → exactly 1 run; renaming a header pauses the sheet before any rule runs and
  opens a Class B flag; bot edits never re-trigger.
- **M5** Onboarding agent. Exit: plain-English instruction for the reference
  workbook → valid config → dry-run → approval → live, no hand-editing;
  malformed instruction ends in human ticket, never a bad ACTIVE config.
- **M6** Repair agent + weekly audit. Exit: benign rename produces an
  approvable patch that resumes the sheet; STATUS-column deletion produces an
  ambiguous-question flag, no patch; injected new enum value opens Class C flag.
- **M7** Dashboard. Exit: full loop (enroll→approve→run→flag→patch→undo)
  performable entirely from the UI.

Definition of done for the MVP overall: 3 real sheets enrolled by instruction,
2 weeks of runs, zero invariant violations in logs.
